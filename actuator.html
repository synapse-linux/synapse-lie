Is it ready?

Use readiness before inference.

The management listener defaults to http://127.0.0.1:19880. /actuator/health/liveness is 200 while the HTTP loop serves, even if the model has not loaded. /actuator/health/readiness and /actuator/health return 200 only when the model and executor are ready; otherwise they return 503. Both bodies are short status objects.

Check readiness
curl -i http://127.0.0.1:19880/actuator/health/readiness

# Ready: HTTP 200  {"status":"UP"}
# Loading/unavailable: HTTP 503  {"status":"OUT_OF_SERVICE"}

A 200 readiness response confirms the executor opened; it is not a numerical or performance qualification. The model routes are on the API listener, port 8000 in the server example. Calling /actuator there returns 404.

Counters and export

Find a name, then inspect its samples.

First request /actuator/metrics to get registered names. A detail response contains name, description, baseUnit, measurements and availableTags. Counter measurements use COUNT, gauges use VALUE, and timers expose COUNT, TOTAL_TIME and MAX. A filter can repeat; all specified tag pairs must match. Unknown or unmatched metric details return 404; malformed filters return 400.

Find and filter a metric
curl --fail http://127.0.0.1:19880/actuator/metrics
curl --fail 'http://127.0.0.1:19880/actuator/metrics/http.server.requests?tag=method:GET'
curl --fail http://127.0.0.1:19880/actuator/prometheus

Successful Actuator JSON uses application/vnd.spring-boot.actuator.v3+json. The Prometheus route uses text/plain; version=0.0.4; charset=utf-8. The metrics contract defines individual counters and their accounting scope.

Scheduler and cache

Read state without guessing from a zero.

GET /actuator/llm returns schema:"synapse-lie.llm.v1" and ready. Its backend describes the engine, model, state, context and capabilities; cache reports RAM and disk checkpoint counters; scheduler reports queued, active, blocked and finished requests. The nested scheduler.executor identifies the current phase and prefill/decode call and batch counts.

Inspect a running server
curl --fail http://127.0.0.1:19880/actuator/llm

With no worker, the response has the following shape; with a worker, backend, cache and scheduler become objects with live fields:

No-model response
{"schema":"synapse-lie.llm.v1","ready":false,"backend":null,"cache":null,"scheduler":null,"memory":null,"speculation":null,"throughput":null,"latency":null}

Top-level memory, speculation, throughput and latency are currently null, meaning unsupported or unknown, not measured zero. Use benchmark JSONL for per-run prefill and decode rates.

Live operator control

Change the next request's prefill chunk.

The server can report or change prefill_chunk at runtime. POST exactly one integer field, prefill_chunk, between 1 and 32,768 and no larger than the capacity reserved at startup. The response includes the effective prefill_chunk, prefill_capacity, revision and applies_to:"new_requests". It does not rewrite already admitted or queued requests.

Read and change the chunk
curl --fail http://127.0.0.1:19880/actuator/llm/prefill
curl --fail http://127.0.0.1:19880/actuator/llm/prefill \
  -H 'Content-Type: application/json' \
  -d '{"prefill_chunk":16384}'

An invalid body returns 400, a value above the startup capacity returns 409, and an unavailable core returns 503. Setting the existing value leaves the revision unchanged. This is a server control, not a synapse-lie-bench option.

Status and access

Treat management access as operational access.

Unknown routes return 404, unsupported methods 405 and unexpected queries 400. Errors are JSON under error, with type, param, code and message. An unready health check returns 503 with its status body rather than the error envelope. There is no built-in authentication or TLS. Keep the management listener on loopback or a trusted, controlled network.
