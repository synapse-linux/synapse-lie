The running service

Server settings change the live model.

synapse-lie-server loads one model per process, serves /v1 on the API listener and serves /actuator on a separate management listener. Its defaults are useful for a smoke test; set context and active slots deliberately for real use. A benchmark's matching labels only describe the server it observed.

Typical local start
build/strix-halo/synapse-lie-server \
  --model /path/to/first-shard.gguf --model-id qwen3.8-flash-next \
  --host 127.0.0.1 --port 8000 --context 262144 --max-active 1
Choose model files →Main GGUF, optional MTP predictor and vision projector.Monitor the process →Health, cache, scheduler and prefill control responses.

Run synapse-lie-server --help on your build for accepted limits. The table below covers the canonical flags of develop.

Optional model parts

Load only what the request needs.

--model-mtp points to a compatible predictor; --mtp-draft-tokens sets its draft budget. --model-vision points to a projector for PNG/JPEG requests. Both are separate from --model and have their own admission and qualification limits. The models page links directly to candidate files and explains pairing.

Flag lookup

Every server option, grouped by job.

Search for a setting or open one of the two groups. Cache flags change retained inference state, not model weights or stored OpenAI response records.

Server

Listeners, model and request limits

These flags belong to synapse-lie-server. With no --model, it serves management only and readiness stays unavailable.

Show server settings ⌄
OptionWhat it controls
--helpPrint server usage and exit without opening a model.
--build-infoPrint compiled backend, source pin and build metadata as JSON; no model load.
--host IPv4Inference listener address. Default 127.0.0.1; use 0.0.0.0 for a trusted LAN client.
--port numberInference listener TCP port. CLI default 19879; site examples use 8000.
--management-host IPv4Separate actuator/monitor listener address; default 127.0.0.1.
--management-port numberSeparate actuator/monitor port; default 19880. It cannot share the same address and port as inference.
--model first-shard.ggufModel path. For a split GGUF, give shard 00001 and keep all shards together; requires a GPU-enabled build for original-weight inference.
--model-id idPublic model name in /v1/models and requests. Default qwen3.8-flash-next in a normal build.
--model-mtp fileExplicit compatible MTP predictor GGUF. Required when using a nonzero MTP draft budget; experimental original-weight qualification remains separate.
--mtp-draft-tokens numberMTP predictor draft-token budget; default 0. Requires --model-mtp when nonzero.
--model-vision fileExplicit compatible vision projector GGUF for PNG/JPEG image inputs; experimental and requires vision-enabled build.
--context numberMaximum physical tokens per sequence, including prompt, template and output. Allowed 128–1048576; CLI default 4096. Actual memory fit and quality require validation.
--rope-scaling native|yarn2|yarn4Position-scaling profile. Select an explicit YaRN profile above the model's native context; default native.
--prefill-chunk numberMaximum prompt tokens dispatched at once. Allowed 1–32768; default 2048.
--prefill-capacity numberReserve provider capacity separately from the current prefill chunk, up to 32768. Defaults to the chunk.
--max-active numberActive sequences, 1–8; default 1. Multiple ready decoders may form a native batch.
--request-timeout-ms numberAccepted inference request deadline including queue, preparation and output; default 600000 ms.
--response-store-ram-mb numberRAM limit for stored Chat/Responses records, separate from KV retention; default 64 MiB.
--response-store-records numberMaximum stored response/completion records; default 128.
--response-store-ttl-seconds numberStored-record lifetime; default 3600 seconds.
--dir-steering-file fileExperimental layer-major direction bank; requires a model. Numerical GPU quality is not yet qualified.
--dir-steering-ffn valueInitial FFN direction scale from -100 to 100; default 1 when a bank is loaded.
--dir-steering-attn valueInitial attention direction scale from -100 to 100; default 0 when a bank is loaded.

Saved state

KV cache and checkpoint policy

These flags configure cache policy on the server. The shared-core benchmark accepts related settings but owns a separate run. Disk settings concern inference state, never model weights.

Show cache and checkpoint settings ⌄
OptionWhat it controls
--kv-cache-ram-mb numberRAM budget for retained KV checkpoints; default 4096 MiB, 0 disables retention.
--kv-disk-dir pathAbsolute private directory for persistent checkpoints. Off unless all three disk flags are supplied.
--kv-disk-space-mb numberDisk quota for retained checkpoints; required with --kv-disk-dir.
--kv-disk-staging-mb numberRAM staging budget for checkpoint transfers; required with --kv-disk-dir.
--kv-cache-policy ds4|legacyCheckpoint capture schedule; default ds4 on the develop build. legacy selects the earlier policy.
--kv-cache-min-tokens numberMinimum reusable prefix length; default 512 tokens.
--kv-cache-cold-max-tokens numberCold checkpoint capture threshold; default 30000 tokens.
--kv-cache-continued-interval-tokens numberInterval between continued-session checkpoint candidates; default 10000 tokens, aligned to the boundary setting.
--kv-cache-boundary-trim-tokens numberTail tokens excluded when selecting a stable retained boundary; default 32.
--kv-cache-boundary-align-tokens numberAlignment of stable checkpoint boundaries; default 2048.
--kv-cache-text-prefix on|offAllow text-prefix matching for checkpoint reuse; default on.
--kv-cache-capture-finish on|offCapture a reusable checkpoint when a request finishes; default on.

Older --prefix-* and --cache-* spellings remain accepted aliases. Prefer the canonical --kv-* names above; the alias map in develop is authoritative.
