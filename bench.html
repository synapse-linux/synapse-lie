The benchmark to use

Advance one corpus through exact context frontiers.

synapse-lie-bench reads a GGUF and a raw UTF-8 corpus, then writes raw JSONL evidence. The corpus walk is the meaningful path for the requested context curve: each point times only the newly appended physical tokens, followed by a separate decode probe. Graph export belongs to that same run.

The current develop binary calls this ds4-walk and still defaults to single. The requested source change will rename the walk corpus-walk, make it the default and add DS4-style flags and real decode concurrency. Until it lands, the command below uses the CLI that actually works. fresh, http-curve and http-multi remain in the current binary but are not part of the recommended benchmark path.

Commands that work today

Use the included corpus first.

Set LIE_MODEL to the first GGUF shard and create results/. The repository already contains a pinned copy of Manzoni's I promessi sposi at data/bench/promessi_sposi.txt. This short walk stops at 8K; omit --sizes to advance in 2K steps through 128K.

Incremental corpus walk · graph included
mkdir -p results
build/strix-halo/synapse-lie-bench --suite ds4-walk \
  --model "$LIE_MODEL" --corpus data/bench/promessi_sposi.txt \
  --pp 2048 --sizes 2048,4096,6144,8192 \
  --output results/walk-8k.jsonl --graphs results/walk-8k

Direct model timing

What does the corpus walk measure?

The benchmark tokenizes the raw UTF-8 file once, without a chat template. For every measured repetition it starts an empty sequence, then advances through exact physical-token frontiers. With --pp 2048, the first point processes tokens 1–2048; the next restores or replays that pre-decode prefix and times only tokens 2049–4096. It repeats this pattern at 6144, 8192 and every requested frontier.

FrontierTimed prefillAfter prefill
2048Empty → 2048: 2048 new tokensDecode up to 128 tokens; retain pre-decode prefix.
4096Restored 2048 → 4096: 2048 new tokensDecode again from this frontier.
6144Restored 4096 → 6144: 2048 new tokensContinue the same logical walk.

The first point is a full 2K prefill; later points measure the same new-token count at deeper context. Prefill and decode have separate monotonic timestamp intervals. Model loading and corpus tokenization are outside PP/TG. State capture and restore/replay are outside those intervals too, with their own recorded durations. --restore auto uses a bounded state snapshot when available, otherwise replay; --restore replay forces replay. A new repetition starts from zero. The current implementation is C1 direct inference. Decode concurrency is a requested source change and is not yet measured by this walk.

Graph option

Graphs belong to the run.

Add --graphs NEW-DIRECTORY to a supported measurement suite. After a complete run, the native C reporter reads the just-written JSONL and creates summary.csv, summary.json, benchmark.svg and benchmark.png. --compare REFERENCE-JSONL adds a matched peer and requires --graphs.

The existing --suite report path is an offline re-export utility for completed evidence; it does not measure a model and is not part of the normal benchmark flow. The state correctness suite does not generate PP/TG plots. A graph export failure returns nonzero while leaving raw JSONL intact.

Detailed option lookup

Current benchmark options, grouped by purpose.

The corpus walk is above. The tables below document current flags, including specialized diagnostic paths retained in this build. --help on the installed binary is authoritative.

Direct benchmarks

Direct executor suites

single, multi, fresh, loading and memory use the GPU executor without HTTP. The current binary defaults to single. These are specialized diagnostics; fresh is pending deprecation. The latter two are diagnostics: loading is affected by OS file cache, while memory is not an allocation-exact HIP peak.

Growing context

Incremental corpus walk

The current CLI name ds4-walk tokenizes one UTF-8 corpus and appends exactly --pp new tokens at each frontier. Its requested new name is corpus-walk, with DS4-style --prompt-file, --ctx-start, --ctx-max, --step-incr, --step-mul, --gen-tokens and LIE-specific --concurrency. Those flags are not accepted by this build; see the current timing method above. Checkpoint and restore/replay times are outside PP and TG.

Shared engine

Shared C inference core

Use --suite core to time the shared reactive engine, admission and KV behavior. It is direct inference, without the HTTP listener. Supply exactly one input source: raw UTF-8 --prompt-file or a JSON integer array --tokens-file. Raw text does not add a chat template. It also accepts related shared KV options.

Canonical conversation

Cached HTTP context curve

http-curve follows the Gufo-style sequential conversation protocol. It calibrates token counts, prepares each depth with an actual short assistant reply, then times the next turn. It needs a running server with enough context and prefix retention; the server must supply executed phase timings and cache counts in a schema this parser accepts.

Concurrent requests

Legacy prepared HTTP cohorts

The client prepares each session before measuring simultaneous decode, with one stable client ID per participant. The server needs prefix retention and enough active slots. Preparation prefill, sum of server request rates and common-wall output rate are separate results; the server must supply executed phase timings and cache counts in a schema this parser accepts.

Persistent cache

KV persistence across restart

--suite http-kv-disk runs write and read phases against a server configured with RAM retention off, KV disk on and at least two active slots. The operator restarts the server between phases. The tool never restarts it. http-ssd remains an alias.

Offline utility

Re-export existing evidence

--suite report is retained for offline re-export, not as a benchmark measurement. It reads completed JSONL without opening model weights. Reports contain summary.csv, summary.json, benchmark.svg and benchmark.png. Output artifacts must not already exist. Failed evidence is rejected rather than averaged.
