# Exact native corpus benchmark

The corrected native `synapse-lie-bench` uses the raw *I promessi sposi*
corpus, with the same bytes as the owner's DS4 measurements. Provenance is in
[`data/bench/README.md`](../data/bench/README.md). Behavioral reference:
[`antirez/ds4` at 0aaea5a2](https://github.com/antirez/ds4/blob/0aaea5a238fb41a35106a551e73c8409dfb751ac/ds4_bench.c).
No DS4 engine code or sibling-workspace artifacts are imported.

The model tokenizer converts the unchanged text to a token array, using its
required sizing/fill passes. Every prompt is an exact prefix of that array.
There is no chat template, word-count search, repeated padding or tolerance.
A short corpus or unaligned requested size fails explicitly.

## Measurement

`single` times the next `--pp` tokens after a preceding prefix. The prefix is
replayed into an empty sequence outside the PP/TG timers. This implements
DS4's incremental measurement interval without claiming DS4's snapshot/restore
implementation. `fresh` separately times the entire prompt from an empty
sequence. The scopes must not be merged into one comparison.

For chunk 2K, the default final frontiers are 2048, 4096, 8192, 16384,
32768, 65536, 131072; 4K and 8K start at their respective chunk sizes.
Every prefill call consumes a complete chunk. The 128K frontier contains
131072 physical tokens, before generation. No intermediate tail is inserted.

```sh
synapse-lie-bench --suite single --model MODEL.gguf \
  --prompt-file data/bench/promessi_sposi.txt \
  --pp 2048 --prefill-chunk 2048 --tg 128 \
  --context-capacity 133760 --warmups 0 --repetitions 1 \
  --output exact-2k.jsonl --graphs exact-2k-report
```

Use 4096 or 8192 for both PP and chunk to select the other grids.
Output paths must be new. Execution remains greedy AR, with EOS respected;
TG uses the actual completed token count and records whether the requested
budget was completed. This is not DS4's ignore-EOS mode.

`--suite report` validates exact targets, physical IDs and hashes, phase
counts, complete chunks and zero tail. It exports CSV, JSON, SVG and PNG.
New HTTP text calibration fails when its target cannot be reached exactly;
HTTP-curve default tolerance is zero. Explicit legacy tolerance and request
replay remain separate HTTP capabilities, not this native corpus contract.

## Build and validation

The feature branch owns a reproducible private source capsule, generated by
`tools/prepare-q2-exact-bench.py` from the recorded native bench source. Its
patch and file hashes are tracked. `cmake/exact-bench` links the latest retained
Q2 numerical archives; 923/923 device functions match the qualified chunk
server byte for byte. Reference executables are not rebuilt.

On `.157`, both focused CTests pass: 23 CLI cases in Debug and the same 23
under ASan/UBSan/LSan. They cover 2K/4K/8K, exact IDs through 128K, short
corpora, unaligned grids and tampered report counters. These use an explicitly
synthetic executor and provide no model-performance or numerical evidence.
Receipt: `evidence/q2-exact-bench-preparation/ctest.json`.

GPU plan: `config/q2-exact-bench128-plan.json`. IOMMU remains enabled.
The previous HTTP tables with 130925 and other unaligned counts are retained
as historical observations; they do not satisfy the requested exact-grid
experiment and are not a performance baseline for this different corpus.
