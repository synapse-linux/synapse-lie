Where to send requests

Point your client at the model listener.

The example server in the usage guide listens at http://127.0.0.1:8000. OpenAI clients use http://127.0.0.1:8000/v1 as their base URL. Set --model-id when starting the server, then use that ID in requests. One server process currently loads one model.

Discover, then generate
curl --fail http://127.0.0.1:8000/v1/models
curl --fail http://127.0.0.1:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.8-flash-next","messages":[{"role":"user","content":"Hello"}],"max_tokens":128}'

Use the discovered ID if your server loads a different model. The management listener defaults to 127.0.0.1:19880; it does not serve /v1.

Model catalog

Read the live model ID.

GET /v1/models returns an OpenAI-style list. While the worker is loading or unavailable, data is empty. When ready, the list contains the loaded model with id, object:"model", owned_by, context_length and max_output_tokens. GET /v1/models/{id} returns that model or 404 for an unknown ID.

While the model is unavailable
{"object":"list","data":[]}

The ready catalog reports configured capacity. It does not qualify GPU memory fit, answer quality or speed at that context.

Two generation formats

Choose the wire format your client speaks.

Chat Completions

POST /v1/chat/completions accepts messages. A normal response has choices and usage. With "stream":true, it emits SSE Chat chunks and ends with [DONE]. Chat defaults to store:false.

Responses

POST /v1/responses accepts input and optional instructions. It returns a response object or ordered response.* SSE events. It does not use the Chat [DONE] marker. Responses defaults to store:true.

Responses example · stateless
curl --fail http://127.0.0.1:8000/v1/responses \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.8-flash-next","input":"Hello","store":false,"max_output_tokens":128}'

Both formats accept function declarations and return call IDs with arguments. Your client runs each tool and sends the correlated result in a later request; the server does not execute client tools. Streaming needs "stream":true and, with curl, --no-buffer. Text, function calls, supported images, sampling controls and structured output are described in the source contract.

There is no GET /v1/responses list endpoint. Audio, video, embeddings, hosted tools, vector stores and OpenAI cloud administration are outside this model-serving API.

Conversation state

Stored output is local and bounded.

Chat defaults to store:false; Responses defaults to store:true. Stored records live in server RAM, separate from the model's KV cache. Defaults are 128 records, 64 MiB and a one-hour TTL; restart clears them. Use store:false for independent benchmarks. A full store returns 429.

Responses can continue with previous_response_id. background:true lets a job continue after the creating connection closes; retrieve or cancel it by ID. For replay, starting_after is the last received SSE sequence_number. truncation:auto removes oldest complete turns when needed; the default disabled policy rejects prompts beyond the context budget.

Reading failures

Check the HTTP status and error code.

Errors use an error object with type, param, code and message. Invalid fields or context exceedance use 400; unknown model or expired record uses 404; a bounded admission or record store may return 429; unavailable inference returns 503. Unsupported fields are rejected explicitly.

Compatibility boundary. This is an OpenAI-compatible local model API, not the entire OpenAI cloud platform. The Pi guide records a successful GPU tool round trip. The Codex and Claude Code guide names their remaining protocol gaps.
