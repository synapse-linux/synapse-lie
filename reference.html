First, the two programs

Run the model; then measure it.

synapse-lie-server is the long-running OpenAI HTTP service. synapse-lie-bench runs one measurement and saves JSONL. Its --suite flag names the measurement method; it does not change the model or reconfigure a running server.

Server · stays runningsynapse-lie-server

Loads GGUF weights and owns HTTP, context, active slots and KV retention.

--model file --context number --max-active number --host ip-address --port numberNo --suite on the server.
Bench · direct GPUsynapse-lie-bench --suite fresh

Loads a GGUF itself and times the executor without HTTP.

--model file --sizes number,... --tg number --output new-results.jsonlOther direct suites replace fresh, one per run.
Bench · HTTP clientsynapse-lie-bench --suite http

Sends requests to an already running server. It does not load weights.

--url url/v1 --model id --output new-results.jsonlhttp-curve and http-multi are alternative HTTP suites.
Bench · offlinesynapse-lie-bench --suite report

Reads a finished JSONL file and creates graphs and CSV.

results.jsonl --output new-directoryRun this afterward as a separate command.

Each bench invocation has one --suite value. You can run the HTTP benchmark while the server is listening; the direct benchmark and report do not require a server.

Who owns each setting?

QuestionSet it on the serverPass it to the benchmark
Which model?--model file loads GGUF weights.Direct methods use --model file; HTTP methods use --model id from /v1/models.
How much context?--context number sets the real sequence capacity.Direct core, ds4-walk and state set their own --context. HTTP --context-capacity checks an expected limit; it cannot enlarge the server.
How many users?--max-active number sets active sequence slots.--users 1,2,4 chooses the cohort sizes to request.
How large is a prefill dispatch?--prefill-chunk number controls the live executor.Direct suites can set their own --prefill-chunk. HTTP suites observe the running server setting.
Is the cache enabled?--kv-cache-ram-mb 0 disables RAM checkpoint retention.In http, --server-kv-cache off records the condition; it does not change it. Direct core can set its own KV budget.

Most comparisons need just one measurement method. Keep the workload, model, GPU, context, cache settings and timing scope the same on both sides.

Server controls

Configure the server before benchmarking.

The http benchmark flag --server-kv-cache off describes what you ran; they cannot turn off the server cache. Start the server with the settings you intend to measure, then record the same conditions in the benchmark.

Model and context

--model opens the first GGUF shard. --context is the per-sequence budget for prompt, template and output. A configured 256K limit does not by itself prove GPU fit or answer quality.

Prompt work

--prefill-chunk bounds a dispatch of prompt tokens. It changes execution shape, not the total prompt length.

Concurrent decode

--max-active sets active server sequences, up to eight. Use a matching active capacity for http-multi.

Reusable state

--kv-cache-ram-mb 0 disables RAM checkpoint retention for a cold test. Disk checkpoints require all three --kv-disk-* settings.

The server walkthrough has a complete launch command. The flag index gives accepted names, ranges and defaults for every server and benchmark option.

What are you trying to learn?

01

How fast is a new prompt?

Use fresh for direct GPU prefill from an empty sequence. Use http --preset prefill when the server and API path are part of the comparison.

Compare full-prompt prefill tokens/s, then decode tokens/s. A warm cache changes the question.

02

How does speed change as a conversation grows?

Use http-curve against a running server. It prepares each depth, then measures the next turn and its output.

Compare newly executed prompt tokens/s at each depth, not all tokens already in the conversation.

03

What happens with several users?

Use http-multi for prepared API requests at C1, C2, C4 and so on. Configure the server's --max-active accordingly.

Compare cohort output tokens/s over shared wall time and individual decode rates separately.

04

Do I need a graph or CSV?

Use report on a completed JSONL file. This step reads evidence; it does not rerun inference.

Produces CSV, JSON, SVG and PNG. A failed or incomplete run is not averaged in.

For an end-to-end command, follow the benchmark walkthrough. The exact accepted options for your executable are printed by synapse-lie-bench --suite name --help.

Numbers with meaning

“Prefill” can describe two different jobs.

Prefill is the model reading prompt tokens; decode is producing output tokens. Both rates are tokens per second. The numerator matters as much as the rate.

Full prompt · fresh

An 8,192-token point times processing all 8,192 tokens from an empty sequence.

New turn · growing-context methods

At an 8,192-token frontier with a 2,048-token step, the measured prefill covers only the 2,048 new tokens. The earlier 6,144 establish context.

These two rates answer different questions and should not share a comparison line. A cache hit can skip executed prefill entirely; record the cached and executed token counts rather than assigning it a zero rate. Decode rate for one request also differs from total cohort output divided by common wall time.

The name that needs explaining

What is ds4-walk?

It is LIE's direct GPU benchmark for the DS4-style growing-context method. “Walk” means it advances through one tokenized text corpus in fixed steps. The name records the comparison method; it is not a model variant or a server feature. The retained Q2/UD comparison used the same byte-identical I promessi sposi corpus as the pinned DS4 control.

2KRead first 2K
4KKeep 2K, read next 2K
6KKeep 4K, read next 2K
8KKeep 6K, read next 2K

At every frontier it times the new 2K prefill and the generated output. Checkpoint creation, restore or replay are recorded separately. It uses raw text without HTTP or a chat template, so use it when you need a matched executor-level DS4 comparison—not as a substitute for an API or full-prompt test.

Short, exact 2K-step walk · direct GPU
mkdir -p results
build/strix-halo/synapse-lie-bench --suite ds4-walk \
  --model /path/to/first-model-shard.gguf \
  --corpus /path/to/promessi_sposi.txt \
  --pp 2048 --sizes 2048,4096,6144,8192 \
  --context 133760 --prefill-chunk 2048 --tg 128 \
  --warmups 0 --repetitions 1 --restore auto \
  --output results/walk.jsonl

The corpus must contain enough tokens for the last frontier. The historical plan records the exact corpus hash and test conditions; this command is only a template until those inputs match. The four rows above do not mean four fresh prompts: they are successive positions in one text. Use fresh --sizes 8192 for a complete new 8K prompt.

All names, one map

Why are there so many suites?

Each name keeps a different timing contract explicit. Direct methods bypass HTTP; served methods include a client request; verification methods check state rather than throughput. Select the question first, then use its name in --suite.

Direct suites also require --model file --output new-results.jsonl. HTTP suites require --url url/v1 --model id --output new-results.jsonl, except where a suite’s own help gives a different required set. The table shows distinctive options; the full flag index and each suite’s --help cover optional limits and defaults.

http-ssd is an older spelling of http-kv-disk, not another method. If you omit --suite, the direct benchmark defaults to single; choose a method explicitly in saved commands.

After the run

Keep the evidence beside the graph.

Every measurement writes a new JSONL file and refuses to overwrite an existing one. The report reads that file offline and produces summary.csv, summary.json, benchmark.svg and benchmark.png.

Export a completed measurement · no model load
build/strix-halo/synapse-lie-bench --suite report \
  results/walk.jsonl --output results/walk-report --label LIE

Compare only files with matching workloads and timing contracts. For a precise flag lookup, use the searchable CLI index or the build's --help. The benchmark method guide covers qualification details.
