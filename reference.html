00 / SCOPE

Find the option for your suite

synapse-lie-bench dispatches each --suite to a different parser. An option shown for core may be invalid for http. Search this page by flag or description; keep a separate output file for every measurement. For exact accepted bounds in your build, run --help or --suite NAME --help.

Showing all options.

Units and validity. Options ending in -mb use binary MiB. PP means executed prompt processing; TG means output decode. A benchmark declaration about a server (cache, context, RoPE) records what you say you configured; it does not change the server. CPU-only builds and --build-info are not model-inference evidence.

01 / SERVER

Listeners, model and request limits

These flags belong to synapse-lie-server. With no --model, it serves management only and readiness stays unavailable.

OptionWhat it controls
--helpPrint server usage and exit without opening a model.
--build-infoPrint compiled backend, source pin and build metadata as JSON; no model load.
--host IPv4Inference listener address. Default 127.0.0.1; use 0.0.0.0 for a trusted LAN client.
--port NInference listener TCP port. CLI default 19879; site examples use 8000.
--management-host IPv4Separate actuator/monitor listener address; default 127.0.0.1.
--management-port NSeparate actuator/monitor port; default 19880. It cannot share the same address and port as inference.
--model FIRST-SHARD.ggufModel path. For a split GGUF, give shard 00001 and keep all shards together; requires a GPU-enabled build for original-weight inference.
--model-id IDPublic model name in /v1/models and requests. Default qwen3.8-flash-next in a normal build.
--model-mtp FILEExplicit compatible MTP predictor GGUF. Required when using a nonzero MTP draft budget; experimental original-weight qualification remains separate.
--mtp-draft-tokens NMTP predictor draft-token budget; default 0. Requires --model-mtp when nonzero.
--model-vision FILEExplicit compatible vision projector GGUF for PNG/JPEG image inputs; experimental and requires vision-enabled build.
--context NMaximum physical tokens per sequence, including prompt, template and output. Allowed 128–262144; CLI default 4096.
--prefill-chunk NMaximum prompt tokens in one prefill dispatch. Allowed 1–2048 on develop; default 2048.
--max-active NActive sequences, 1–8; default 1. Multiple ready decoders may form a native batch.
--request-timeout-ms NAccepted inference request deadline including queue, preparation and output; default 600000 ms.
--response-store-ram-mb NRAM limit for stored Chat/Responses records, separate from KV retention; default 64 MiB.
--response-store-records NMaximum stored response/completion records; default 128.
--response-store-ttl-seconds NStored-record lifetime; default 3600 seconds.

02 / SHARED STATE

KV cache and checkpoint policy

These names are accepted by the server and shared-core benchmark. The state suite accepts the disk trio but has its own --kv-disk-mode. Disk settings concern inference state, never model weights.

OptionWhat it controls
--kv-cache-ram-mb NRAM budget for retained KV checkpoints; default 4096 MiB, 0 disables retention.
--kv-disk-dir PATHAbsolute private directory for persistent checkpoints. Off unless all three disk flags are supplied.
--kv-disk-space-mb NDisk quota for retained checkpoints; required with --kv-disk-dir.
--kv-disk-staging-mb NRAM staging budget for checkpoint transfers; required with --kv-disk-dir.
--kv-cache-policy ds4|legacyCheckpoint capture schedule; default ds4 on the develop build. legacy selects the earlier policy.
--kv-cache-min-tokens NMinimum reusable prefix length; default 512 tokens.
--kv-cache-cold-max-tokens NCold checkpoint capture threshold; default 30000 tokens.
--kv-cache-continued-interval-tokens NInterval between continued-session checkpoint candidates; default 10000 tokens, aligned to the boundary setting.
--kv-cache-boundary-trim-tokens NTail tokens excluded when selecting a stable retained boundary; default 32.
--kv-cache-boundary-align-tokens NAlignment of stable checkpoint boundaries; default 2048.
--kv-cache-text-prefix on|offAllow text-prefix matching for checkpoint reuse; default on.
--kv-cache-capture-finish on|offCapture a reusable checkpoint when a request finishes; default on.

Older --prefix-* and --cache-* spellings remain accepted aliases. Prefer the canonical --kv-* names above; the alias map in develop is authoritative.

03 / BENCH DIRECT

Direct executor suites

single, multi, fresh, loading and memory use the GPU executor without HTTP. Default suite is single. The latter two are diagnostics: loading is affected by OS file cache, while memory is not an allocation-exact HIP peak.

OptionWhat it controls
--suite NAMESelect single, multi, fresh, loading or memory; the other suites below have their own parsers.
--model FILEFirst model GGUF shard; required for direct executor measurements.
--output NEW-JSONLRaw result file; required and created exclusively, so it cannot overwrite prior evidence.
--depths N,...Occupied-prefix depths in single; default 0,4096,8192,12288,16384,32768,65536,131072.
--sizes N,...Whole-prompt targets in fresh; default 1500,8000,8192,32768,131072,258794.
--users N,...Cohort sizes in multi; default 1,2,4,6,8.
--pp NNew suffix tokens after an occupied prefix (or each prepared user); default 2048. In fresh, --sizes sets the full prompt instead.
--tg NMaximum generated tokens per sequence; default 128.
--warmups NExcluded warmup samples per point; default 1.
--repetitions NMeasured samples per point; CLI default 1.
--execution reactive|serialChoose native ready-batch decode or serial interleaving; default reactive.
--graphs DIRECTORYExport report graphs after a successful run into a new directory.
--compare REFERENCE-JSONLCompare matched evidence while exporting graphs; requires --graphs.
--build-infoEmit backend/build identity without opening the model.
--helpPrint direct-suite usage; no model run.

04 / BENCH CORE

Shared C inference core

Use --suite core to time the shared reactive engine, admission and KV behavior. It is direct inference, without the HTTP listener. Supply exactly one input source: raw UTF-8 --prompt-file or a JSON integer array --tokens-file. Raw text does not add a chat template. It also accepts all shared KV options.

OptionWhat it controls
--suite coreSelect the shared-core parser and timing contract.
--model FILEFirst target-model GGUF shard; required.
--output NEW-JSONLRequired raw evidence file, created exclusively.
--prompt-file FILEPlain UTF-8 prompt file, with no automatic chat template.
--tokens-file FILEJSON array of physical token IDs; alternative to --prompt-file.
--context NCore sequence capacity; default 4096, bounded by provider context.
--chunk NCore prefill dispatch chunk, 1–2048; default 2048.
--users NConcurrent jobs 1–8; default 1.
--tg NMaximum output tokens per job; default 128.
--warmups NExcluded warmups; default 0.
--repetitions NMeasured runs; default 3.
--timeout-ms NPer-run deadline; default 600000 ms.
--temperature XSampling temperature 0–2; default 0 (greedy). Nonzero temperature requires --seed.
--seed NReproducible sampling seed, up to signed 64-bit maximum; omitted for default greedy.
--top-p XNucleus probability cutoff in (0,1]; default 1.
--frequency-penalty XFrequency repetition penalty from -2 to 2; default 0.
--presence-penalty XPresence repetition penalty from -2 to 2; default 0.
--model-mtp FILEExplicit compatible MTP predictor GGUF for a separate core run.
--mtp-draft-tokens NMTP draft-token budget; requires predictor for nonzero values.
--model-vision FILEVision projector GGUF. Pair with --image-file and a prompt file.
--image-file FILEPNG/JPEG input for an explicitly vision-enabled core run.
--reactive-probeFunctional output-credit/cancellation probe. Requires physical tokens, two users, TG≥16, one repetition, no warmup/cache/vision. Not a throughput score.
--graphs DIRECTORYGenerate a report after a successful core run into a new directory.
--build-infoEmit build identity without model execution.
--helpPrint core-specific usage.

05 / BENCH HTTP

Served request workloads

--suite http is a native C client for a running API server. It does not start, reconfigure or clear that server. Select one generated --preset or a saved --requests corpus, never both.

OptionWhat it controls
--suite httpSelect the served HTTP parser.
--url URLRunning OpenAI API base URL ending in /v1; required.
--model IDServer model alias used in request bodies; required.
--output NEW-JSONLRequired raw evidence file; existing files are refused.
--server-label IDHuman-readable server identity recorded with the result; required.
--server-kv-cache off|on|unknownDeclaration of the server’s actual cache setup; required, does not change it. --cache-policy is a legacy alias.
--preset NAMEGenerate prefill, decode, conversation or long-context requests; alternative to --requests.
--requests FILEReplay a JSONL request corpus; alternative to a generated preset.
--sizes N,...Generated prompt-token targets. Defaults vary by preset; a long-context target does not raise server capacity.
--tg NRequested output tokens; default 256, or 64 for long-context.
--warmups NExcluded request runs; default 0.
--repetitions NMeasured request runs; default 3.
--turns NConversation turns for the conversation preset; default 20.
--context-capacity NDeclared server context for fit checks; required for long-context, does not alter the server.
--rope-scaling native|yarn2|yarn4Declared server RoPE profile; required for long-context, default otherwise unknown.
--corpus-seed NSeed of the generated long-context corpus; recorded in result identity.
--request-options FILEJSON object merged into generated HTTP request bodies; use the same options for matched runs.
--export-requests NEW-JSONLSave generated request bodies for replay and comparison.
--timeout SECONDSWhole HTTP request deadline; default 630 seconds, 3600 for long-context.
--graphs DIRECTORYExport report graphs after a complete run.
--compare REFERENCE-JSONLCompare a matched reference while exporting; requires --graphs.
--helpPrint HTTP-suite usage.

06 / BENCH HTTP MULTI

Prepared HTTP cohorts

The client prepares each session before measuring simultaneous decode, with one stable client ID per participant. The server needs prefix retention and enough active slots. Preparation prefill, sum of server request rates and common-wall output rate are separate results.

OptionWhat it controls
--suite http-multiSelect the prepared-cohort HTTP client.
--url URLRunning API base URL ending in /v1; required.
--model IDServer model alias; required.
--requests JSONLRequired case corpus with id and body.messages; optional expected prompt count.
--server-label NAMEServer identity in the result; required.
--output NEW-JSONLRaw evidence path; required and exclusive.
--users N,...Prepared cohort sizes; default 1,2,4,6,8.
--tg NGenerated tokens per participant; default 128.
--context-capacity NDeclared server context for prompt/output fit; default 4096, does not reconfigure it.
--warmups NExcluded prepared cohorts; default 1.
--repetitions NMeasured prepared cohorts; default 3.
--timeout SECONDSComplete HTTP cohort deadline; default 630 seconds.
--graphs DIRECTORYExport phase and cohort graphs after a complete run.
--compare REFERENCE-JSONLCompare a matched server run; requires --graphs.
--helpPrint prepared-cohort usage.

07 / BENCH HTTP KV

KV persistence across restart

--suite http-kv-disk runs write and read phases against a server configured with RAM retention off, KV disk on and at least two active slots. The operator restarts the server between phases. The tool never restarts it. http-ssd remains an alias.

OptionWhat it controls
--suite http-kv-diskSelect the native KV disk HTTP client.
--url URLRunning API base URL ending in /v1; required.
--management-url URLActuator origin of the same server; required for state/accounting checks.
--model IDServer model alias; required.
--provider IDProvider identity expected in the server’s reported backend; required.
--cases JSONRequired prompt cases shared by write and read phases.
--output NEW-JSONLRaw evidence path, new for each phase.
--phase write|readProduce disk checkpoints or restore after a separate server restart; required.
--chunk NExpected server prefill chunk recorded and checked in the workload; required.
--reference WRITE-SUMMARY.jsonSuccessful write-phase summary used to validate read-phase restore; required only for read.
--repetitions NMeasured cases; default 3.
--timeout SECONDSHTTP request deadline; default 180 seconds.
--overlapOn read, require a real scheduling-overlap witness; a missed window is inconclusive.
--slow-clientOn read, exercise slow-reader/backpressure behavior.
--graphs DIRECTORYExport report artifacts after a complete phase.
--helpPrint KV disk HTTP usage.

08 / BENCH STATE

State restore qualification

--suite state checks saved/restored runtime state with physical token IDs and logits, rather than reporting a serving throughput curve. MTP and vision are unsupported in this suite.

OptionWhat it controls
--suite stateSelect fresh/restored state-pair checks.
--model FILEFirst GGUF model shard; required.
--output NEW-JSONLRequired raw qualification evidence file.
--tokens-file FILERequired JSON array of physical token IDs.
--pp NCheckpoint position within the physical prompt; required, aligned to chunks unless it is the full prompt.
--context NSequence capacity; default 262144.
--chunk NPrefill chunk size, at most 2048; default 2048.
--capture-decode NRAM-only capture after 1–256 generated tokens; requires --pp equal to full input length.
--kv-disk-mode write|readOptional persistent checkpoint phase; write needs an empty store, read needs its prior exact checkpoint.
--kv-disk-dir PATHAbsolute private checkpoint store path; supply with mode, space and staging.
--kv-disk-space-mb NPersistent checkpoint disk quota in MiB; required for disk mode.
--kv-disk-staging-mb NRAM transfer budget in MiB; required for disk mode.
--build-infoEmit backend identity without state testing.
--helpPrint state-suite usage.

09 / BENCH REPORT

Offline graphs and comparison

--suite report reads completed JSONL without opening model weights. Reports contain summary.csv, summary.json, benchmark.svg and benchmark.png. Output artifacts must not already exist. Failed evidence is rejected rather than averaged.

OptionWhat it controls
--suite reportSelect the native C offline exporter.
INPUT-JSONL / --input FILECompleted raw benchmark evidence, supplied positionally or by flag.
--output DIRECTORYRequired new report directory.
--label NAMEPrimary plot label; default LIE.
--compare FILESecond compatible raw result to compare.
--reference-label NAMEComparison plot label; default Gufo reference.
--compare-cache-buildExplicitly permit a core comparison whose cache build/policy fields differ; requires --compare and records those differences.
--helpPrint report usage without reading evidence.
