Engine model support

The native engine has Qwen3.8 paths and an optional, limited GLM53 provider. Support depends on the selected provider, weight format and recorded profile.

Models with lie-agent

REMOTE build

Connect to a tool-capable Chat Completions server and use the model ID it serves. The server determines model families, formats, templates and inference capabilities. There is no agent-side family allowlist or guarantee for every provider.

NATIVE build

The compiled LIE provider determines model support. A coding session additionally needs tools and multi-message history; a model that passes a raw inference check may not meet those requirements. The limited GLM53 profile therefore does not qualify as an agent coding model.

Previous alpha: exact original-model qualification

The retained alpha archives passed eight controlled C17 cases with Qwen3.8-Flash-Next UD-Q4_K_XL on gfx1150: native and HTTP, individual tools and CodeMode. Profile: context 8192, chunk 2048, output 1024, one active sequence, no MTP or vision.

This is a test configuration, not the complete engine model catalog. Newly compiled REMOTE/NATIVE variants require their own target acceptance. Agent release status · Retained artifact identities.

Model files

For the Unsloth UD-Q4_K_XL profile, keep all four shards from the pinned publisher revision in one directory. Pass the first shard to the engine. The Antirez Q2 GGUF is a separate weight profile.

Engine commands use --model for the file path. A NATIVE agent uses --model-path for the file and --model for its identifier. A REMOTE agent uses the server's model ID. Publisher licenses and model terms apply.

Engine: first shard
LIE_MODEL=/models/UD-Q4_K_XL/Qwen3.8-Flash-Next-UD-Q4_K_XL-00001-of-00004.gguf
build/strix-halo/synapse-lie-server --model "$LIE_MODEL" \
  --model-id qwen3.8-flash-next --port 8000

MTP and vision

UD-Q4 profile

The retained functional check used a separate shared-Q8 MTP head and a separate Q8 vision projector. Those are specific pairings, not approval of every published component.

Recorded MTP head · Recorded vision projector

Q2 profile

The GGUF includes embedded predictor weights. The current source admits embedded or separate predictors with --mtp; its retained development qualifications have separate profiles and limits. Optimization work remains paused.

The embedded-predictor tests apply to their recorded development composition. Q2 vision and lie-agent MTP remain unqualified.

Text inference needs no vision projector. The agent's retained original-model acceptance uses neither MTP nor vision. See server controls for the older command-reference snapshot.

Context and memory

Context capacity includes input, template and reserved output. The engine's software ceiling does not establish memory fit or answer quality for every model. Use a measured model/provider/device profile and explicit RoPE admission. Build and first request · Measure the selected profile.
