Step 1

Build for your GPU.

Install the packages for your distribution first. From the repository root, the normal Strix Halo build is one command; Strix Point uses make strix-point. This compiles the server and native benchmark, but does not download weights.

Strix Halo
make strix-halo

The binaries are under build/strix-halo/. The build guide covers other supported build settings.

Step 2

Get a model file.

Start with the four-shard Unsloth Qwen3.8 Flash Next UD-Q4_K_XL profile. Keep all shards together and pass shard 00001 as --model. The models page has the pinned download, Antirez Q2 status and direct links for optional MTP and vision files.

Step 3

Start lie-server.

This example serves the model API on loopback port 8000 and operations on loopback port 19880. It reserves a 256K-token context; actual fit depends on model and memory.

Run from the repository root
LIE_MODEL=/path/to/Qwen3.8-Flash-Next-UD-Q4_K_XL-00001-of-00004.gguf
build/strix-halo/synapse-lie-server \
  --model "$LIE_MODEL" --model-id qwen3.8-flash-next \
  --host 127.0.0.1 --port 8000 --context 262144

Wait for readiness. A 200 response means the model and executor opened. The management port is separate from /v1; lie-server explains every launch option and /actuator explains each monitoring response.

Check the two listeners
curl --fail http://127.0.0.1:19880/actuator/health/readiness
curl --fail http://127.0.0.1:8000/v1/models

Step 4

Ask one question.

Use the model ID advertised by /v1/models. This example uses Chat Completions; the OpenAI API reference has Responses, streaming, tools, stored records and every implemented route.

First Chat request
curl --fail http://127.0.0.1:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.8-flash-next","messages":[{"role":"user","content":"Hello"}],"max_tokens":128}'

To use an agent, go to agent setup. Pi reads the live model catalog; Codex and Claude Code have separate compatibility notes.

Optional measurement

Measure once and get a graph.

synapse-lie-bench loads the model directly for fresh, measures a new 8K prompt and saves raw JSONL. --graphs is an option on the measurement itself; there is no second benchmark suite to run for a normal graph. Use a new output file and graph directory each time.

One direct GPU measurement
mkdir -p results
build/strix-halo/synapse-lie-bench --suite fresh \
  --model "$LIE_MODEL" --sizes 8192 \
  --output results/fresh-8k.jsonl --graphs results/fresh-8k

The report directory contains summary.csv, summary.json, benchmark.svg and benchmark.png. For a DS4-style growing-context run, served HTTP curve or multi-user test, see lie-bench.
