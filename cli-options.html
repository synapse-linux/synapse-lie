The server owns the live model, context, cache and active slots. The benchmark owns the test workload and output file. Some names overlap: --model is a GGUF file on the server or direct benchmark, but a public model ID in an HTTP benchmark. The ownership map explains the common collisions.

Reading benchmark results. PP is prompt processing; TG is output decoding. A benchmark flag describing server cache or context records the test conditions—it does not change a running server. Check accepted limits with --help on your build.

Server

Listeners, model and request limits

These flags belong to synapse-lie-server. With no --model, it serves management only and readiness stays unavailable.

Saved state

KV cache and checkpoint policy

These names are accepted by the server and shared-core benchmark. The state suite accepts the disk trio but has its own --kv-disk-mode. Disk settings concern inference state, never model weights.

Show cache and checkpoint settings ⌄
OptionWhat it controls
--kv-cache-ram-mb numberRAM budget for retained KV checkpoints; default 4096 MiB, 0 disables retention.
--kv-disk-dir pathAbsolute private directory for persistent checkpoints. Off unless all three disk flags are supplied.
--kv-disk-space-mb numberDisk quota for retained checkpoints; required with --kv-disk-dir.
--kv-disk-staging-mb numberRAM staging budget for checkpoint transfers; required with --kv-disk-dir.
--kv-cache-policy ds4|legacyCheckpoint capture schedule; default ds4 on the develop build. legacy selects the earlier policy.
--kv-cache-min-tokens numberMinimum reusable prefix length; default 512 tokens.
--kv-cache-cold-max-tokens numberCold checkpoint capture threshold; default 30000 tokens.
--kv-cache-continued-interval-tokens numberInterval between continued-session checkpoint candidates; default 10000 tokens, aligned to the boundary setting.
--kv-cache-boundary-trim-tokens numberTail tokens excluded when selecting a stable retained boundary; default 32.
--kv-cache-boundary-align-tokens numberAlignment of stable checkpoint boundaries; default 2048.
--kv-cache-text-prefix on|offAllow text-prefix matching for checkpoint reuse; default on.
--kv-cache-capture-finish on|offCapture a reusable checkpoint when a request finishes; default on.

Older --prefix-* and --cache-* spellings remain accepted aliases. Prefer the canonical --kv-* names above; the alias map in develop is authoritative.

Direct benchmarks

Direct executor suites

single, multi, fresh, loading and memory use the GPU executor without HTTP. Default suite is single. The latter two are diagnostics: loading is affected by OS file cache, while memory is not an allocation-exact HIP peak.

Show direct benchmark settings ⌄
OptionWhat it controls
--suite nameSelect single, multi, fresh, loading or memory; see ds4-walk and the other suites below.
--model fileFirst model GGUF shard; required for direct executor measurements.
--output new-results.jsonlRaw result file; required and created exclusively, so it cannot overwrite prior evidence.
--depths number,...Occupied-prefix depths in single; default 0,4096,8192,12288,16384,32768,65536,131072.
--sizes number,...Whole-prompt targets in fresh; default 1500,8000,8192,32768,131072,258794.
--users number,...Cohort sizes in multi; default 1,2,4,6,8.
--pp numberNew suffix tokens after an occupied prefix (or each prepared user); default 2048. In fresh, --sizes sets the full prompt instead.
--tg numberMaximum generated tokens per sequence; default 128.
--warmups numberExcluded warmup samples per point; default 1.
--repetitions numberMeasured samples per point; CLI default 1.
--prefill-chunk numberDirect prefill dispatch size, 1–32768; default 2048. --chunk remains an alias.
--execution reactive|serialChoose native ready-batch decode or serial interleaving; default reactive.
--graphs directoryExport report graphs after a successful run into a new directory.
--compare reference.jsonlCompare matched evidence while exporting graphs; requires --graphs.
--build-infoEmit backend/build identity without opening the model.
--helpPrint direct-suite usage; no model run.

Growing context

Incremental raw-text walk

ds4-walk tokenizes one UTF-8 corpus, then appends exactly --pp new tokens at each frontier. It measures those new tokens, not the entire accumulated prefix. Checkpoint and restore/replay times are recorded separately from PP and TG.

Show growing-context settings ⌄
OptionWhat it controls
--suite ds4-walkSelect the direct C1 incremental walk; no HTTP or chat template.
--model fileFirst model GGUF shard; required.
--corpus fileRequired raw UTF-8 text, tokenized once for all frontiers.
--output new-results.jsonlExclusive raw evidence file; existing files are refused.
--sizes number,...Increasing physical frontiers, each exactly one --pp step apart. Default advances to 128K.
--pp numberNew tokens appended at every frontier; default 2048.
--tg numberOutput-token budget at each frontier; default 128.
--context numberPhysical sequence capacity, including prompt and output; default 262144, maximum 1048576.
--rope-scaling native|yarn2|yarn4Position-scaling profile for the selected context; default native.
--prefill-chunk numberProvider prefill dispatch size, 1–32768; default 2048.
--restore auto|replayauto uses a bounded checkpoint when supported, otherwise replays. replay forces replay; both are outside PP/TG timers.
--warmups numberExcluded complete walks; default 0.
--repetitions numberMeasured complete walks; default 1.
--graphs directoryExport native graphs and summary into a new directory.
--compare reference.jsonlCompare a matching walk when exporting graphs.

The walk guide explains checkpoint accounting and why fresh answers a different question.

Shared engine

Shared C inference core

Use --suite core to time the shared reactive engine, admission and KV behavior. It is direct inference, without the HTTP listener. Supply exactly one input source: raw UTF-8 --prompt-file or a JSON integer array --tokens-file. Raw text does not add a chat template. It also accepts all shared KV options.

Show shared-core benchmark settings ⌄
OptionWhat it controls
--suite coreSelect the shared-core parser and timing contract.
--model fileFirst target-model GGUF shard; required.
--output new-results.jsonlRequired raw evidence file, created exclusively.
--prompt-file filePlain UTF-8 prompt file, with no automatic chat template.
--tokens-file fileJSON array of physical token IDs; alternative to --prompt-file.
--context numberCore sequence capacity, 128–1048576; default 4096. Long-context profile and GPU fit remain separate.
--rope-scaling native|yarn2|yarn4Core position-scaling profile; default native.
--prefill-chunk number / --chunk numberCore prefill dispatch size, 1–32768; default 2048.
--prefill-capacity numberProvider prefill capacity reserved independently of the current chunk, up to 32768.
--users numberConcurrent jobs 1–8; default 1.
--tg numberMaximum output tokens per job; default 128.
--warmups numberExcluded warmups; default 0.
--repetitions numberMeasured runs; default 3.
--timeout-ms numberPer-run deadline; default 600000 ms.
--temperature valueSampling temperature 0–2; default 0 (greedy). Nonzero temperature requires --seed.
--seed numberReproducible sampling seed, up to signed 64-bit maximum; omitted for default greedy.
--top-p valueNucleus probability cutoff in (0,1]; default 1.
--top-k numberKeep up to this many sampling candidates; 0 disables the cutoff.
--min-p valueMinimum probability ratio in [0,1] for sampling; default 0.
--ignore-eosContinue to the fixed output budget after EOS while recording EOS. Raw-text/token samples only; excluded from vision and reactive probes.
--frequency-penalty valueFrequency repetition penalty from -2 to 2; default 0.
--presence-penalty valuePresence repetition penalty from -2 to 2; default 0.
--model-mtp fileExplicit compatible MTP predictor GGUF for a separate core run.
--mtp-draft-tokens numberMTP draft-token budget; requires predictor for nonzero values.
--model-vision fileVision projector GGUF. Pair with --image-file and a prompt file.
--image-file filePNG/JPEG input for an explicitly vision-enabled core run.
--reactive-probeFunctional output-credit/cancellation probe. Requires physical tokens, two users, TG≥16, one repetition, no warmup/cache/vision. Not a throughput score.
--prefill-probe live|ram|ssdFunctional prefill cancellation or cache-restore check. Requires its documented fixed inputs; not a throughput score.
--progress-ms numberEmit regular JSONL progress snapshots on stderr; 0 disables, otherwise 100–60000 ms.
--dir-steering-file fileExperimental direction bank used by the shared core; requires model and matching steering settings.
--dir-steering-ffn valueInitial FFN scale for the bank, -100–100.
--dir-steering-attn valueInitial attention scale for the bank, -100–100.
--dir-steering-plan fileJSON schedule of bounded steering changes at increasing physical-token frontiers; requires a bank.
--graphs directoryGenerate a report after a successful core run into a new directory.
--build-infoEmit build identity without model execution.
--helpPrint core-specific usage.

HTTP benchmarks

Served request workloads

--suite http is a native C client for a running API server. It does not start, reconfigure or clear that server. Select one generated --preset or a saved --requests corpus, never both.

Show HTTP benchmark settings ⌄
OptionWhat it controls
--suite httpSelect the served HTTP parser.
--url urlRunning OpenAI API base URL ending in /v1; required.
--model idServer model alias used in request bodies; required.
--output new-results.jsonlRequired raw evidence file; existing files are refused.
--server-label idHuman-readable server identity recorded with the result; required.
--server-kv-cache off|on|unknownDeclaration of the server’s actual cache setup; required, does not change it. --cache-policy is a legacy alias.
--preset nameGenerate prefill, decode, conversation, long-context or long-context-recall requests; alternative to --requests.
--requests fileReplay a JSONL request corpus; alternative to a generated preset.
--sizes number,...Generated prompt-token targets. Defaults vary by preset; a long-context target does not raise server capacity.
--tg numberRequested output tokens; default 256, or 64 for long-context.
--warmups numberExcluded request runs; default 0.
--repetitions numberMeasured request runs; default 3.
--turns numberConversation turns (default 20) or 1–2 recall turns with the recall preset.
--context-capacity numberDeclared server context for fit checks; required for long-context, does not alter the server.
--rope-scaling native|yarn2|yarn4Declared server RoPE profile; required for long-context, default otherwise unknown.
--corpus-seed numberSeed of the generated long-context corpus; recorded in result identity.
--request-options fileJSON object merged into generated HTTP request bodies; use the same options for matched runs.
--export-requests new-results.jsonlSave generated request bodies for replay and comparison.
--timeout secondsWhole HTTP request deadline; default 630 seconds, 14400 for long-context presets.
--graphs directoryExport report graphs after a complete run.
--compare reference.jsonlCompare a matched reference while exporting; requires --graphs.
--helpPrint HTTP-suite usage.

Canonical conversation

Cached HTTP context curve

http-curve follows the Gufo-style conversation protocol. It calibrates token counts, prepares each depth with an actual short assistant reply, then times the next turn. It needs a running server with enough context and prefix retention.

Show conversation-curve settings ⌄
OptionWhat it controls
--suite http-curveSelect the native canonical cached-conversation client.
--url urlRunning OpenAI-compatible API base URL ending in /v1; required.
--model idPublic model ID sent in each request; default bench.
--server-label nameIdentity shown in results and charts; default LIE.
--endpoint-profile openai|gufoRequest-control profile for the target endpoint; default openai.
--output new-results.jsonlRequired exclusive raw result file.
--depths number,...Target cached-prefix depths; default 0,4096,8192,12288,16384,32768,65536,131072.
--pp numberNew prompt tokens for the measured turn; default 2048.
--tg numberRequired output budget for that turn; default 128.
--context-capacity numberDeclared server capacity for fit checks; default 133760. Does not reconfigure the server.
--mode ar|mtpRecord and request autoregressive or MTP mode; MTP requires a separately configured server.
--task namePinned prose, repetition, copy, story or thinking recipe; default prose.
--seed numberCorpus recipe seed; default 1.
--warmups numberExcluded turns per depth; default 1.
--repetitions numberMeasured turns per depth; default 1.
--depth-tolerance valuePermitted relative token-count error at each prepared depth; default 0.005.

The method guide explains calibration, retries, cached-token checks and how to compare another server.

Concurrent requests

Prepared HTTP cohorts

The client prepares each session before measuring simultaneous decode, with one stable client ID per participant. The server needs prefix retention and enough active slots. Preparation prefill, sum of server request rates and common-wall output rate are separate results.

--server-label nameServer identity in the result; required.

Persistent cache

KV persistence across restart

--suite http-kv-disk runs write and read phases against a server configured with RAM retention off, KV disk on and at least two active slots. The operator restarts the server between phases. The tool never restarts it. http-ssd remains an alias.

Show persistent-KV test settings ⌄
OptionWhat it controls
--suite http-kv-diskSelect the native KV disk HTTP client.
--url urlRunning API base URL ending in /v1; required.
--management-url urlActuator origin of the same server; required for state/accounting checks.
--model idServer model alias; required.
--provider idProvider identity expected in the server’s reported backend; required.
--cases jsonRequired prompt cases shared by write and read phases.
--output new-results.jsonlRaw evidence path, new for each phase.
--phase write|readProduce disk checkpoints or restore after a separate server restart; required.
--chunk numberExpected server prefill chunk recorded and checked in the workload; required.
--reference write-summary.jsonSuccessful write-phase summary used to validate read-phase restore; required only for read.
--repetitions numberMeasured cases; default 3.
--timeout secondsHTTP request deadline; default 180 seconds.
--overlapOn read, require a real scheduling-overlap witness; a missed window is inconclusive.
--slow-clientOn read, exercise slow-reader/backpressure behavior.
--graphs directoryExport report artifacts after a complete phase.
--helpPrint KV disk HTTP usage.

State verification

State restore qualification

--suite state checks saved/restored runtime state with physical token IDs and logits, rather than reporting a serving throughput curve. MTP and vision are unsupported in this suite.

--output new-results.jsonlRequired raw qualification evidence file.

--kv-disk-staging-mb numberRAM transfer budget in MiB; required for disk mode.

Reports

Offline graphs and comparison

--suite report reads completed JSONL without opening model weights. Reports contain summary.csv, summary.json, benchmark.svg and benchmark.png. Output artifacts must not already exist. Failed evidence is rejected rather than averaged.

Show graph and report settings ⌄
OptionWhat it controls
--suite reportSelect the native C offline exporter.
results.jsonl / --input fileCompleted raw benchmark evidence, supplied positionally or by flag.
--output directoryRequired new report directory.
--label namePrimary plot label; default LIE.
--compare fileSecond compatible raw result to compare.
--reference-label nameComparison plot label; default Gufo reference.
--compare-cache-buildExplicitly permit a core comparison whose cache build/policy fields differ; requires --compare and records those differences.
--helpPrint report usage without reading evidence.
