For a working agent path today, use the separate Pi setup guide. The examples below refer to the server started with --model-id qwen3.8-flash-next --host 0.0.0.0 --port 8000. On the same machine, use 127.0.0.1; from another machine, replace SERVER-IP with the server’s trusted LAN address.

Needs a Responses change

Codex CLI

Official OpenAI documentation supports custom providers with a base URL and wire_api = "responses". Put this profile in your user-level ~/.codex/synapse-lie.config.toml (or $CODEX_HOME/synapse-lie.config.toml). Codex ignores provider definitions in a project-local .codex/config.toml. The profile uses no API key because LIE has no built-in API authentication. OpenAI configuration reference ↗

View the unqualified Codex profile ⌄
Codex profile · configuration only
model = "qwen3.8-flash-next"
model_provider = "synapse_lie"
model_context_window = 262144
model_reasoning_summary = "none"

[model_providers.synapse_lie]
name = "Synapse LIE"
base_url = "http://SERVER-IP:8000/v1"
wire_api = "responses"
requires_openai_auth = false

Once LIE implements the missing request fields and passes an agent tool round trip, the selection command will be codex --profile synapse-lie. Do not treat the profile above as a working integration today. A local no-GPU probe with Codex CLI 0.159.3 confirmed it sends POST /v1/responses with reasoning, include: ["reasoning.encrypted_content"], prompt_cache_key and client_metadata. The develop Responses parser rejects unknown fields and does not accept those values, so the request fails before inference.

Completion gate. LIE needs a defined policy for these request fields, then tests for a streamed text turn, a function-call/result round trip, long-context budgeting and session continuation. The profile only proves that Codex selects the local provider and reaches the right URL.

Needs a different API

Claude Code

Claude Code’s ANTHROPIC_BASE_URL selects an Anthropic-format gateway. It does not convert requests to OpenAI Chat Completions or Responses. LIE develop has no /v1/messages endpoint, so setting ANTHROPIC_BASE_URL=http://SERVER-IP:8000 will not connect it. Anthropic’s current gateway documentation also states that routing Claude Code to non-Claude models through a gateway is not supported by Anthropic.

A future interoperable path needs an independently maintained Anthropic Messages adapter or gateway that translates request, streaming event, tool-use and tool-result semantics to LIE’s OpenAI API. It must be tested with a complete Claude Code tool round trip before publishing configuration commands. No direct Claude Code profile is shipped or qualified on develop.

Use Pi now for agent work. Pi is the documented and exercised client. Codex and Claude Code remain explicit integration tasks; setting only a base URL does not close either protocol gap.

Connect across machines

Address and access

For a remote client, start LIE with --host 0.0.0.0 --port 8000 and use http://SERVER-IP:8000/v1 in OpenAI clients. The management port is separate and defaults to 127.0.0.1:19880. LIE has no built-in TLS or access control, so keep port 8000 on a trusted network or behind a configured proxy. Readiness is available at http://127.0.0.1:19880/actuator/health/readiness on the server host.

For exact server flags and benchmark parameters, use the lie-server option reference. The OpenAI API reference lists all model routes; the lie-bench guide explains measurement settings.
